# Смажена Кава

Адаптивний сайт кавового магазину: каталог із 20 сортів, конструктор власного міксу, квіз для підбору кави та кошик.

**[Відкрити сайт](https://smazhena-kava-lab10.vercel.app/)** · [Репозиторій](https://github.com/bogdan-kifa/smazhena-kava)

## Можливості

- Каталог: пошук, фільтри, сортування, обране та швидкий перегляд.
- Конструктор: до чотирьох сортів, пропорції, вага, обсмаження зеленого зерна, помел і вибір пакування з фото.
- Квіз: швидкий і докладний підбір кави з рекомендаціями.
- Кошик, демонстраційне оформлення, профіль, історія замовлень і збережені мікси.
- Форма контактів із клієнтською валідацією та доступним модальним підтвердженням.
- Карусель відгуків Swiper.js, галерея способів приготування Fancybox та ефект друку Typed.js.
- Довідкові сторінки про каву, доставку й оплату, запитання та відповіді, інтерактивна карта країн-виробників.

## Поточний режим

У `js/site-config.js` увімкнено `demo: true`. Опублікована версія не потребує бази даних.

Кошик, обране, чернетка міксу, демопрофіль і демозамовлення зберігаються у браузері. Це не справжня авторизація: поля паролів демонструють інтерфейс, їх значення не перевіряються, не передаються й не зберігаються. Дані не синхронізуються між пристроями.

Контактна форма імітує надсилання після перевірки полів. Реальні платежі, доставка, листи й відновлення пароля не підключені. Контакти та умови магазину на сторінках є прикладами.

## Технології

HTML5, CSS, Tailwind CSS 3, Vanilla JavaScript. Шрифти Inter і Lora зберігаються локально. Swiper 11.2.10, Fancybox 5.0.36 і Typed.js 2.1.0 підключені через CDN. Для обмеженого руху враховано `prefers-reduced-motion`.

## Локальний запуск

Для перегляду демоверсії достатньо відкрити папку в VS Code та запустити `index.html` через Live Server. Відкриття через `file://` не підходить для ресурсів, що завантажуються через `fetch`.

Для роботи з інструментами проєкту потрібні Node.js 24 та pnpm:

```sh
pnpm install --frozen-lockfile
pnpm start
```

Адреса локального сервера: <http://127.0.0.1:3000/>. Деморежим сайту залишається ввімкненим і при такому запуску.

## Команди

| Команда | Призначення |
| --- | --- |
| `pnpm start` | Локальний сервер |
| `pnpm dev` | Сервер із перезапуском після змін |
| `pnpm build` | Генерація спільної розмітки та статичної папки `public/` |
| `pnpm build:css` | Оновлення зібраного Tailwind CSS |
| `pnpm watch:css` | Перезбирання Tailwind під час роботи |
| `pnpm format` | Форматування HTML, CSS та JavaScript |
| `pnpm test:backend` | Окремі тести збереженого бекенду; потрібен Node.js 24 |

## Структура

```text
*.html                 Сторінки сайту
products/              Сторінки сортів кави
assets/                Фото, відео, шрифти, іконки та дані карти
css/                   Дизайн-токени, Tailwind та стилі компонентів
js/                    Каталог, конструктор, квіз і взаємодія
server/layouts/        Спільні шаблони шапки та підвалу
server/build.cjs       Статична збірка для Vercel
server/                Збережений локальний бекенд і його тести
vercel.json            Налаштування публікації
```

Каталог і характеристики беруться з `js/products.js`. Правила ваги, помелу, обсмаження й пакування визначені у `js/commerce-rules.js`. Медіакомпоненти головної сторінки налаштовуються в `js/media-components.js` і `css/media-components.css`.

Шапку й підвал редагуйте в `server/layouts/header.html` та `server/layouts/footer.html`, після чого виконуйте `pnpm build`. Готова розмітка включається у сторінки до запуску JavaScript.

## Публікація

Окремий проєкт Vercel **smazhena-kava-lab10** відстежує гілку **lab10-media**.

- Application Preset: `Other`.
- Build Command: `node server/build.cjs`.
- Output Directory: `public`.
- База даних і секретні змінні для демоверсії не потрібні.

Папка `public/` створюється під час збірки й не комітиться. Серверний код, локальна база та `.env` не копіюються у статичний результат. Зміни в `lab10-media` запускають оновлення окремого сайту; `main` містить актуальний код.

## Збережений бекенд

Код у `server/` залишено для подальшої серверної реалізації. Він не обслуговує опубліковану демоверсію. Для локальної роботи з ним встановіть `demo: false`, використовуйте Node.js 24 і запустіть `pnpm start`. Локальні дані створюються у `.data/`; ця папка виключена з Git.

Повернення справжньої авторизації на хостинг потребує окремого налаштування API та PostgreSQL. Поточний `vercel.json` призначений для статичної публікації, а серверний обробник збережено у `server/deployment-backup/`.
