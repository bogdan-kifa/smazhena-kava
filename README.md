# Смажена Кава

Кавовий магазин: каталог із 20 сортів, конструктор міксу, квіз, кошик, особистий кабінет та історія замовлень.

## Локальний запуск

Потрібні Node.js 24 та pnpm.

```sh
pnpm install --frozen-lockfile
pnpm start
```

Відкрити http://127.0.0.1:3000/ . Сервер одночасно віддає сайт і API. Live Server підходить лише для статичного перегляду; акаунти та замовлення потребують цього сервера.

Локальна база SQLite створюється у `.data/store.sqlite`. Вона зберігає акаунти, мікси й замовлення між перезапусками. Не видаляйте `.data`, якщо потрібні ці дані. База, `.env`, залежності й зібрана папка `public` виключені з Git.

## Що працює

- Реєстрація, вхід, вихід. Паролі хешуються scrypt із випадковою сіллю; сеанси використовують HttpOnly/SameSite cookies. У базі зберігається лише хеш токена сеансу.
- Профіль: ім’я, телефон, адреса, зміна пароля. Зміна пароля завершує попередні сеанси.
- Збереження названих міксів в акаунті, перегляд, редагування чернетки, перейменування, видалення й повторне додавання в кошик.
- Оформлення з акаунта та без реєстрації, оплата при отриманні. Сервер перевіряє параметри й повторно рахує ціну за `js/products.js`.
- Історія показує лише замовлення поточного користувача. Зберігається знімок складу та ціни на момент оформлення.
- Гостьове підтвердження захищене окремою HttpOnly cookie, доступне лише в браузері оформлення протягом доби. Гостьові покупки автоматично не прив’язуються до акаунта за email.
- Повторний запит із тим самим ключем не створює друге замовлення. Для зміненого кошика потрібен новий ключ.

Онлайн-оплата, перевірка email, відновлення пароля, Google-вхід, листи, відстеження перевізника, складський облік та адміністративне керування статусами ще не підключені. Нові замовлення мають статус «Прийнято». Створення запису у базі не запускає реальну доставку чи списання коштів.

Кошик, обране й чернетка конструктора залишаються браузерними. Вони не синхронізуються між пристроями. Збережені в акаунті мікси й історія завантажуються із сервера.

## Форма контактів — ЛР №9

`contacts.html`, `css/contacts.css`, `js/contacts.js`: ім’я, email, обов’язковий телефон, тема, повідомлення, згода. Є клієнтська валідація, підказки біля полів, зведення помилок, доступне модальне підтвердження. Ця форма залишається демонстраційною: звернення не передаються та не зберігаються. Після перевірки вона прямо повідомляє про імітацію надсилання. Старий `js/validation.js` збережено як попередню реалізацію ЛР, але сторінка його не підключає.

## Перевірка

```sh
pnpm test:backend
pnpm build
```

Серверні тести використовують окрему тимчасову базу та перевіряють авторизацію, ізоляцію акаунтів, cookies, ціну, повторні запити, гостьовий доступ і збереження між перезапусками. Матеріали браузерних перевірок зберігаються окремо від репозиторію.

## Розміщення з PostgreSQL

Підготовлено адаптер PostgreSQL і конфігурацію Vercel. Онлайн-розміщення та підключення віддаленої бази ще не виконувалися.

1. Створити PostgreSQL-базу й отримати захищений рядок підключення.
2. Додати `DATABASE_URL` у секретні змінні середовища хостингу, а `APP_ORIGIN` — точний HTTPS origin сайту без кінцевого `/` (наприклад, `https://your-project.vercel.app`). Значення не комітити. Зразок назв — у `.env.example`.
3. Node.js 24, команда збирання `pnpm build`, статичний результат `public`, серверний обробник `api/index.js` та правила `vercel.json`. Таблиці створюються автоматично при першому API-запиті.
4. Перевірити реєстрацію, вихід, оформлення та ізоляцію даних уже на хостингу. Для preview-домену потрібен відповідний `APP_ORIGIN` і окрема тестова база.

У production SQLite заборонено: без `DATABASE_URL` API повертає помилку замість створення тимчасової бази. Не вимикайте перевірку TLS для PostgreSQL. GitHub Pages і звичайний статичний Netlify без функцій цей API не виконують. Перед публікацією потрібні реальні контакти, умови магазину, резервне копіювання бази й моніторинг; приклади не є готовою юридичною політикою.

[Конфігурація Vercel](https://vercel.com/docs/project-configuration/vercel-json).

## Структура та робочий процес

- `server/` — HTTP-сервер, API, перевірка цін, SQLite/PostgreSQL, тести.
- `api/index.js`, `vercel.json` — адаптер для Vercel.
- `js/api-client.js` — клієнт запитів того самого origin.
- `profile.html`, `orders.html`, `js/cabinet.js` — кабінет.
- `login.html`, `js/auth-ui.js` — форма входу й реєстрації.
- `my-mixes.html`, `js/saved-mixes.js` — рецепти акаунта.
- `checkout.html`, `order-confirmation.html`, `js/checkout.js` — оформлення й підтвердження.
- `js/products.js` — єдине джерело каталогу для клієнта й сервера.
- `css/style.css` — дизайн-токени, `css/tailwind.css` — зібрані утиліти.

Для ЛР №8 і №9 використовується один репозиторій `bogdan-kifa/smazhena-kava`. Стан ЛР №8 збережений тегом `lab-08-final`. Поточні зміни бекенду й останнього оформлення контактів локальні: без коміту, push або розгортання до окремої вказівки.


### Спільні елементи та правила

Шапку та підвал редагуйте в `server/layouts/header.html` і `server/layouts/footer.html`, потім запускайте `npm run build`. Генератор оновить HTML усіх сторінок, відносні шляхи та активні пункти меню. Сайт зберігає готову розмітку й працює без JavaScript.

Вага, помел, обсмаження, пакування й правило наявності спільні для браузера та сервера в `js/commerce-rules.js`. Історія завантажується сторінками; гостьові підтвердження доступні протягом доби для кожного замовлення.

Регресійні перевірки: `node --test server/tests/*.test.cjs`. Тести використовують окремі тимчасові бази даних.


### Статичний деморежим ЛР №9

У `js/site-config.js` увімкнено `demo: true`. Профіль, мікси й демозамовлення зберігаються в окремому ключі localStorage; поля паролів залишені для вигляду, їх значення не перевіряються, не передаються й не зберігаються. Це не справжня авторизація. Вихід закриває демопрофіль, не стираючи дані; очищення браузера їх видаляє. Гостьові замовлення не додаються до історії профілю. Контактна форма залишається навчальною імітацією.

Vercel: Other, build `node server/build.cjs`, output `public`; база та змінні середовища не потрібні. Автоматичні API-функції вимкнені.

Справжній бекенд залишено в `server/`. Для локального повернення до нього встановіть `demo: false` та запустіть `npm start`. Для майбутнього серверного деплою відновіть `api/index.js` із `server/deployment-backup/api/index.js` і серверний vercel.json з резервної копії в матеріалах лабораторної; налаштуйте PostgreSQL та APP_ORIGIN.
